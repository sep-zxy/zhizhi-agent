01架构设计原则与核心 ADR（会议拍板转译）

将会议讨论的每一条业务结论，固化为不可违背的架构决策记录（Architecture Decision Records）

编号 架构决策 核心方案与硬性约束 规避的工程风险
ADR-01 V1 原生多人隔离
账号基座		 所有关系表、全文索引、向量索引、OSS 对象键与内存会话全部强制以 user_id 为一级租户键；V1 直接交付登录鉴权与租户上下文中间件。本地单人部署复用同一架构，仅默认初始化单账号。 彻底避免“先做单人再迁多人”导致的表结构重写、索引重构与越权漏洞。
ADR-02 插槽式来源插件
可拆卸		 所有知识来源封装为实现统一 SourcePlugin 协议的可拆卸插槽（支持进程内插件与外部 MCP Server 两种挂载模式）。卸载任一插件（如抖音/B站）不影响系统主干运行。 隔离高维护成本站点（强反爬）变更，支持直接二开开源解析器并独立热替换。
ADR-03 统一 MD 中间层 + AI 子循环
核心解耦		 任何原始资料（PDF/HTML/视频/Git Commit）禁止直入 Agent 主循环；先在独立异步的解析子循环中完成表格重排、图片提取上传 OSS、Git 架构总结，经 StandardMarkdownSchema 校验后落地。 防止巨量噪声/破损格式撑爆主循环上下文、拉低对话与制卡输出质量。
ADR-04 Git 剥离代码，保留架构抽象
内容规范		 跨端 Git 采集器（Win/Mac）及解析子循环将多条 Commit 去噪归并，仅保留「背景问题 → 架构决策 → 权衡方案」的抽象 Markdown，不保留原仓库代码快照、不强绑定原仓库；出题需代码时由 AI 现编独立伪代码。 避免知识卡依赖易失仓库路径、陷入局部语法细节，保证知识点公共性与复用度。
ADR-05 单一问答入口 + 工具动态裁剪
Agent 编排		 合并日常问答与查库为唯一问答页入口。主循环默认挂载「查个人知识库 + 联网搜索兜底」工具；「生成知识卡」与「各类题型（V1 选择题，V1.5 判断/填空/问答/伪代码）」均封装为独立 Tool，由前端开关在每次请求时动态过滤下发给 LLM 的 Tools 白名单。 替代不可靠的纯自然语言意图识别，实现“关掉就不可能误调”的确定性控制，且支持随时插入新题型。
ADR-06 预设情境多页 + 页内有限调整
受控动态 UI		 按功能类别划分为问答、搜索、知识来源、Wiki、知识地图、独立错题等独立页面，每页预设固定情境骨架；仅允许用户与 Agent 在页内卡片槽做有限调整（投放白名单预设卡片 + 右上角「钉住」防覆写）；状态按 user_id × page_scene 持久化记忆。 既保留 Agent 操控页面的灵动体验，又大幅收敛前端复杂度，避免单画布承载过多情境导致失控。
ADR-07 强绑定 1:N 题库 + 入库双题 + 判重
后半程定稿		 拆出独立 card_questions 表强绑定 card_id（支持 1:N 多题挂靠）。新卡保存立即返回，后台异步默认生成2 道选择题（① 认知理解 + ② 情境应用预测，可设开关）；多文档补卡或更新时，将 Diff 与已有题摘要送入覆盖度判断，仅对未覆盖点增量补题；复习优先抽未做/错题并允许追加新题。 避免保存接口阻塞与重复出同质化题目，同时让同一知识卡持续沉淀多文档、多轮复习题池。
ADR-08 独立错题页解耦 + 地图驱动雷达
后半程定稿		 错题设立独立页面，与知识库入库流程完全解耦，仅作客观练题记录并支持归档与删除防积压；知识雷达显式依赖知识地图，基于图谱拓扑与节点掌握/错题状态识别缺口并推荐下一张待学知识卡。 防止错题逻辑耦合入库事务或无限积压失效；让雷达推荐建立在可解释的知识地图结构之上。
ADR-09 全栈 TS + Pi Agent 内核 + DSH 门禁
基座定稿		 参考 DeepSeek Harness 工程规范自建 pnpm Monorepo（非强绑 DSH alpha 内核）；后端与 Agent 主/子循环统一接入 @earendil-works/pi-agent-core + @earendil-works/pi-ai（无密钥自动走官方 fauxProvider 跑真循环）；全仓启用双编译面、Branded ID、oxlint type-aware 与 5 条静态门禁；Python 开源解析器通过独立 MCP 插槽接入。 前后端 100% 共享 Zod 契约与类型，4 人并行 + AI 辅助写代码不漂移，同时保留外部 Python 生态扩展力。
ADR-10 零 Docker 双驱动 + 零 DOM 移动就绪
基座定稿		 数据库统一 Drizzle ORM PostgreSQL 语法：本地零 Docker 默认嵌入式 PGlite 落盘，填 DATABASE_URL 无缝切标准 PG；对象存储 LocalFs / S3 双驱动；异步队列直接基于 async_jobs 表实现（V1 去掉 Redis 强制依赖）。前端拆出零 DOM 的 @zhizhi/client-core，React Web 预配 PWA 与移动底栏，为 Capacitor / RN 铺路。 不绑死 Docker、拉下代码 5 秒可跑、裸机与容器部署一套代码零分叉，后续做手机端零逻辑重写。

03插槽式知识来源与统一 Markdown 中间层设计

可拆卸来源插件（Slot / MCP 双适配）+ AI 解析子循环 + 运行时 Schema 校验

插槽式插件架构（内置 Slot + 外部 MCP 统一抽象） 可热拆卸

所有来源不直接硬编码在业务代码里，而是向 SourcePluginRegistry 注册。针对高变更站点（如 B 站、抖音、小红书）或开源文档解析器，支持两种零侵入挂载：

  • 内置进程插件（In-Process Slot）：适用于稳定轻量解析（Markdown、HTML、纯文本 PDF、Git 总结接收端），直接实现 IngestAdapter 接口。
  • 外部 MCP / 微服务插件（Out-of-Process MCP）：适用于强反爬视频抓取、复杂 PDF 版面解析（如二开 MinerU / Docling 等开源项目）、V1.5 ASR/OCR。通过标准 MCP Tool 协议启动/动态发现，挂掉或移除后自动降级提示，绝不拖垮主服务。
  • 热插拔容错：注册表维护每个插件的健康状态与能力声明（supported_mime / url_patterns）；当某插件被禁用或卸载时，对应来源入口自动灰显并给出“手动粘贴正文”兜底。

AI 解析子循环（Sub-Loop）与 Git 架构抽象流水线 主从隔离

复杂原料在进入主循环前，先由后台 Worker 驱动专用解析子循环（可选性价比更高的轻模型）执行 4 步提纯：

  • Step 1 原始提取：插件产出原始文本块、原始表格片段、原始图片/关键帧二进制流或原始 Commit Diff。
  • Step 2 媒体托管：所有图片统一上传对象存储，生成租户隔离路径 oss://u/{user_id}/assets/{sha256}.webp（本地单人可映射为 /assets/{user_id}/... 相对路径），MD 中仅存规范引用。
  • Step 3 AI 子循环结构化：PDF 跨页表格重排为标准 GFM 表格；图文/视频按要点分节并标注时间戳锚点；Git 提交执行去噪归并 + 架构抽象总结（彻底剥离原始代码片段，只保留动机、方案与架构权衡）。
  • Step 4 运行时 Schema 校验：通过 Zod / Pydantic 校验 Frontmatter 必填项与正文章节结构，合格后写入 raw_sources 并放行至统一三出口。

  • 完全解耦入库流程：错题表（wrong_book）仅消费练题提交事件做客观记录，不阻塞也不反向修改 Wiki 入库或草稿流。
  • 防积压生命周期：支持 active → archived（归档） 与 deleted（删除） 操作，独立错题页默认只看活跃错题，可切 Tab 回看归档记录。
  • 重做与变式：每条错题绑定原 question_id 与出题时的 card_version_no，支持重做原题或生成变式题。

知识地图 ──▶ 知识雷达依赖链 V1 显式化

  • 前置依赖知识地图：雷达引擎不孤立盲猜，直接读取 wiki_edges 关系图谱与每张卡的题库作答掌握度（已掌握 / 未练 / 高错题）。
  • 缺口定位算法：识别用户已掌握集群的外围缺失前置/进阶节点与薄弱桥接点，输出 2~3 张「下一张待学知识卡」建议及推荐理由。
  • 闭环回流：用户点击采纳后才进入待学清单，避免被动塞垃圾任务。

  • 按功能划分独立页面：明确区分「问答页 / 搜索页 / 知识来源页 / Wiki 页 / 知识地图与雷达页 / 独立错题页」，每个页面都有固定预设情境与传统直达交互，移动端天然契合分页导航。

  • Pin 钉住双向保护：用户点击卡片右上角钉住按钮 → 前端更新状态并按 page_scene 落库 → 请求携带 pinned_slots → 后端拦截覆写指令，改投空闲槽或提示用户。

三层交互记忆系统（按情境页无缝续接）

  • ① 情境页工作区快照（page_canvas_states）：按 (user_id, page_scene, session_id) 记录该页卡片槽的 card_type、ref_id、动态 payload_json（如未提交的题目选项）与 is_pinned 状态，退出重登 100% 续接。
  • ② 用户交互习惯记忆（user_memories）：记录常驻开关偏好（题型开关、入库自动出题开关、默认讲解风格）与常用模型路由，每次进入主循环自动注入轻量 Profile。
  • ③ 对话情节与引用保护（chat_messages）：长会话滚动摘要，被知识卡引用的关键对话轮次加锁保留摘录，删除旧会话不断出处链。

-- 1. 强绑定知识卡的独立 1:N 题库表（支持多文档补卡判重与重复复习挂靠）
CREATE TABLE card_questions (
  id               UUID PRIMARY KEY,
  user_id          UUID NOT NULL REFERENCES users(id),
  card_id          UUID NOT NULL REFERENCES wiki_cards(id) ON DELETE CASCADE,
  card_version_no  INT  NOT NULL,
  source_id        UUID,  -- 触发本次补题的来源文档(如 PDF/Word)，可选
  tool_type        VARCHAR(24) NOT NULL, -- 'mcq' | 'tf' | 'blank' | 'qa'
  dimension        VARCHAR(32) NOT NULL, -- 'understanding' | 'scenario_prediction'
  coverage_summary TEXT NOT NULL,        -- 考点一句话摘要，供改卡判重
  question_json    JSONB NOT NULL,       -- 题干、选项、标准答案与详尽解析
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 2. 与入库完全解耦的独立错题表（支持归档与删除防积压）
CREATE TABLE wrong_book (
  id              UUID PRIMARY KEY,
  user_id         UUID NOT NULL REFERENCES users(id),
  question_id     UUID NOT NULL REFERENCES card_questions(id),
  card_id         UUID NOT NULL,
  card_version_no INT  NOT NULL,
  status          VARCHAR(16) NOT NULL DEFAULT 'active', -- 'active' | 'archived' | 'deleted'
  wrong_count     INT  NOT NULL DEFAULT 1,
  last_wrong_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  archived_at     TIMESTAMPTZ
);
-- 3. 按独立情境页粒度的受控状态持久化表
CREATE TABLE page_canvas_states (
  id           UUID PRIMARY KEY,
  user_id      UUID NOT NULL REFERENCES users(id),
  page_scene   VARCHAR(32) NOT NULL, -- 'chat_qa' | 'search' | 'sources' | 'wiki' | 'map' | 'wrong_book'
  session_id   UUID,
  slots_json   JSONB NOT NULL,       -- [{slot_id, card_type, ref_id, is_pinned, payload}]
  updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (user_id, page_scene, session_id)
);

-- 4. 用户交互习惯与开关记忆表（含入库自动出题开关 + 题型开关）
CREATE TABLE user_memories (
  user_id            UUID PRIMARY KEY REFERENCES users(id),
  auto_quiz_on_save  BOOLEAN NOT NULL DEFAULT true, -- 入库异步生成2道选择题开关
  ui_switches_json   JSONB NOT NULL DEFAULT '{
    "skill_gen_card": false,
    "quiz_tools": { "mcq": true, "tf": false, "blank": false, "qa": false }
  }'::jsonb,
  habit_profile      JSONB NOT NULL DEFAULT '{}'::jsonb,
  updated_at         TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 行级安全兜底 (PostgreSQL RLS 全表统一开启)
ALTER TABLE card_questions ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_iso_questions ON card_questions
  USING (user_id = current_setting('app.current_user_id')::uuid);

1. 接口鉴权层

每个请求经 JWT / Collector PAT 解析出 user_id 并写入请求级上下文；严禁信任前端请求体传入的 user_id。

2. 数据库 RLS 兜底

ORM 仓储层自动拼接 WHERE user_id = ?，同时在 PostgreSQL 开启 Row-Level Security（RLS）做数据库级双保险。

3. 检索与向量隔离

全文检索与向量相似度检索必须将 user_id 作为前置过滤条件，杜绝 RAG 跨账号串库泄露隐私笔记。

4. 对象存储隔离

所有图片、截帧与原文件统一落盘至 u/{user_id}/...，通过后端签名 URL 或鉴权代理访问，不暴露公网裸链。
