01四域架构全景：工具域、插件域与主循环如何切边界

把「平台差异」和「跨平台公共加工」物理隔离，让新增平台插件保持在 ~150 行薄适配层

知枝四域分层与数据流总图
Plugin Domain Capability Domain Ingest Pipeline Pi Agent Runtime

关键设计收益：抖音插件只做「口令识别 + 调 DTK MCP + 数据映射」；字幕解析、无字幕 ASR 补齐、字幕时间轴定位重点截图、对象存储隔离、AI 解析子循环全部沉淀在公共层，B 站/小红书/YouTube 插件接入时直接零成本复用。

1. 来源插件域

Plugin

只管「这个平台怎么拿原料」

  • 识别 URL / 分享口令
  • 调平台原生协议或外部 MCP
  • 返回元信息、原生字幕、媒体引用或图集
  • 通过标记告诉管线「缺不缺 ASR / 截图」

2. 公共能力域

Capability

跨平台共享的确定性底座

  • cap-mcp-client：HTTP/stdio MCP
  • cap-asr：可插拔语音转写（带时间戳）
  • cap-media-frames：字幕清洗 + 定向截图
  • storage：u/{userId}/assets/* 隔离

3. 解析编排域

Pipeline

把原料洗成标准 Markdown

  • 运行在 DbJobQueue 异步队列
  • 按策略编排「字幕 → ASR → 截图 → 子循环」
  • 执行 StandardMarkdownSchema 强校验
  • 落 raw_sources 并按三出口分流

4. Agent 工具域

Pi Agent

主对话循环的克制白名单

  • 仅消费已净化的 StandardMarkdown
  • 按 UI 开关每轮硬裁剪 Tools
  • 制卡必须先投递 wiki_draft_diff 预览
  • 零 Shell、零爬虫凭证暴露

02视频 / 图文通用 5 步流水线与「字幕定位重点截图」兜底策略

所有视频类来源（抖音、B 站、YouTube、本地视频）共用同一条降级容错链路

STEP 1 · 平台提取

抖音插件调用 DTK v5

match() 识别口令/短链 → 调 DTK parse_url。若是图文，直接拉原图进 binaryAssets 跳过 ASR；若是视频，调 download_media 获取媒体引用。

STEP 2 · 字幕/ASR

字幕优先，按需补齐

按优先级：平台官方字幕 → DTK 离线 FunASR → 公共 AsrProvider（百炼 / 硅基 / faster-whisper），统一归一化为 TranscriptSegment[]。

STEP 3 · 重点截图

字幕定位 + 三级兜底

子循环读带时间戳文稿，选 3~6 个关键时间点（如图表/公式/结论）交 FFmpeg 精准截帧；无时间戳则等分 3 帧；无视频流则退回封面图。

STEP 4 · 子循环洗稿

独立 LLM 生成标准 MD

把图集/关键帧按 u/{userId}/assets/* 落盘为 asset://，再调 runPiSubLoopTask() 产出带出处、图注、时间锚点与候选主题的 Markdown。

STEP 5 · 校验与出口

落 raw_sources 走三出口

StandardMarkdownDocumentSchema 强校验 → 写 raw_sources → 按 disposition 进仅归档、待学队列，或生成知识卡草稿待用户确认保存。

字幕定位重点截图 · 三级确定性降级表（B 站 / 抖音 / YouTube 通用） packages/capabilities/media-frames
降级档位 触发条件 执行策略 产出质量与成本
L1 精准定位（最优） 存在带 startSec/endSec 的字幕或时间戳 ASR，且有可读取的视频流/本地文件 子循环先读字幕 JSON，输出 3~6 个 { timestampSec, caption } → FFmpeg -ss 精准定向抽帧转 WebP 图配文高度贴合，仅 3~6 张图，不耗多模态大模型逐帧 Token
L2 均匀抽帧兜底 仅有整段纯文本（如 DTK 默认 FunASR 无时间戳输出），但有视频流与总时长 跳过首尾片头片尾（15% / 50% / 85% 分位点）等分抽取 3 张代表帧 零额外 ASR 成本，保证知识卡有基本画面参考
L3 封面/图集兜底 仅音频、无视频下载权限、或 FFmpeg 未安装/执行失败 视频退回下载 cover_url 单图；图文笔记直接保留全部无水印原图 永不因截图失败导致整条采集任务崩溃，主干高可用

// packages/ingest/plugin-douyin-dtk —— 路线 A 薄适配层与 DTK v5 MCP 工具映射

1. healthcheck()
   └─ 调用 DTK MCP: pool_status（零消耗身份池）
   └─ 若未配置 DTK_MCP_URL 或连接超时 → 返回 { ok: false, detail: 'DTK sidecar offline' }（绝不抛错阻断主服务）

2. match(input)
   └─ 校验 input.url 或 input.rawText 是否包含 v.douyin.com / douyin.com/(video|note|jingxuan)

3. extract(input, tenant, runtime)
   ├─ 阶段 fetching_meta (15%): 调用 DTK MCP parse_url({ url })
   │   ├─ 若返回 status='pending' → 自动轮询 get_task_result({ task_id })（支持 AbortSignal 取消）
   │   └─ 拿到归一化 metadata：aweme_id / title / desc / author / type(video|gallery) / cover / images[]
   ├─ 若为 图文笔记 (gallery):
   │   └─ 下载无水印原图进 binaryAssets，设置 needsAsr: false, needsKeyframes: false，直接返回 Bundle
   └─ 若为 短视频 (video):
       ├─ 阶段 downloading_media (40%): 调用 DTK MCP download_media({ platform: 'douyin', content_id })
       ├─ 阶段 transcribing (70%):
       │   ├─ 若 DTK 已启用 FunASR 且未强制要求逐句时间戳 → 调 transcribe_video({ download_id })
       │   └─ 否则返回 mediaRef + needsAsr: true，交由知枝公共 AsrProvider 产出带时间戳段落
       └─ 设置 needsKeyframes: true，由公共管线完成「重点帧定位 + 兜底截图 + 资产落盘 + AI 子循环」

  • 双面隔离门禁（scripts/verify-workspace-deps.ts）：把 @zhizhi/cap-*、@zhizhi/ingest-pipeline、@zhizhi/plugin-* 加入 FORBIDDEN_FOR_CLIENT 与 FORBIDDEN_FOR_SHARED，杜绝前端与共享契约反向依赖。
  • 租户隔离门禁（scripts/verify-tenant-scope.ts）：raw_sources 写入与查询严格走 withTenant(db, tenant, ...)；所有图片/截图通过 StorageProvider.put(tenant.userId, ...) 落盘。

  • 零 Docker 本地可跑：未配置 DTK_MCP_URL 时，pnpm dev 与 pnpm test 全部使用 Mock / 可选降级，不强依赖 Docker。

07开工前只需拍板的 2 个设计点

确认后即可直接按 M1 → M2 开始编码实现

决策 1 · 公共能力域的物理目录

推荐选项 A

选项 A（推荐）：独立建顶层域 packages/capabilities/{mcp-client,asr,media-frames}，与 packages/ingest/* 并列。未来 OCR、PDF 解析、网页抓取、Git 摘要都能平等复用，不绑定“采集”语境。

选项 B：收敛放在 packages/ingest/capabilities 单包内，包数量更少，但未来非采集模块复用时边界略模糊。

决策 2 · 转写与重点截图的默认档位

推荐选项 1

选项 1（推荐）：默认优先用 DTK 自带的离线 FunASR（免 API Key、速度快）+ L2 等分/封面兜底截图；一旦用户配置了带时间戳的 AsrProvider（百炼 paraformer-v2 / 本地 faster-whisper），自动升级为 L1 字幕定位重点帧截图。

选项 2：默认走云端时间戳 ASR（如百炼/硅基），DTK 仅负责解析与媒体下载，从第一天就默认启用 L1 精准时间点截图（需配 ASR API Key）。
